# 标准库架构设计规范

技术选型：前端 HTML/CSS/JS，后端 FastAPI，数据库 PostgreSQL，文件存储 MinIO（S3 协议）。

架构分为两部分：横向层贯穿所有业务线，当前只有多进程任务管理；纵向线包含四条进程驱动的异步写路径：采集线、解析线、索引线、可视化投影线。前端请求驱动的同步读路径不合并为单一业务线，而是按界面和能力拆成若干独立读取能力。

标准状态由两个正交维度组成。官网状态由外部来源决定：国家标准和行业标准取值为即将实施、现行、废止；地方标准取值为现行、有更新版、废止。加工状态由内部流水线推进，取值为已下载、已材料化、已索引，以及不可下载、下载失败、材料化失败、索引失败。

**有效标准 = 官网状态有效 ∧ 已材料化 ∧ 已索引**，三者缺一不可。官网状态有效指国家标准和行业标准为现行，地方标准为现行或有更新版。采集线、解析线、索引线推进全量标准加工；可视化投影线基于有效标准集生成首页散点图产物；请求型读取能力作用于有效标准集。有效标准过滤是查询层的默认约束，不是业务层可选参数。

## 横向层：多进程任务管理

横向层负责所有后台长任务的运行管理。它横跨采集线、解析线、索引线和可视化投影线，解决“任务什么时候执行、由哪个进程执行、执行到哪里、失败后怎么办、历史效果如何查看”的问题。

可以把多进程管理理解为后台流水线的总调度层。它负责启动各条纵向线，并在上游任务完成后按规则创建下游任务；各纵向线只定义被启动后的业务处理规则。

```text
多进程任务管理
  -> 启动采集线：历史采集、周期更新
      -> 采集线产生可解析 PDF 后，创建解析任务
          -> 解析线成功后，创建索引任务
              -> 索引集合变化或周期更新结束后，创建可视化投影任务
```

因此，多进程管理不是第五条业务线，也不替代采集线、解析线、索引线和可视化投影线。它管理这些纵向线的任务实例、进程、状态、进度和历史记录。

### 职责边界

多进程任务管理只负责任务生命周期和进程调度，不负责各条纵向线内部的业务处理。

它回答的是“何时启动哪条线、是否允许启动、启动后怎么监控、结束后怎么衔接下一条线”。它不回答“这条线内部如何完成业务”。

它负责：

- 创建后台任务记录。
- 启动、监控和回收任务进程。
- 控制不同任务之间的并发和互斥。
- 持续记录任务状态、阶段、进度、心跳和统计结果。
- 在任务失败、进程异常退出或心跳超时时更新任务状态，并按规则决定是否重试。
- 为首页摘要提供最近周期更新状态和任务统计。

它不负责：

- 国家标准、行业标准、地方标准网站如何翻页和解析。
- PDF 如何下载、存储和材料化。
- Markdown 如何生成。
- embedding 如何生成和写入 pgvector。
- Embedding Atlas 二维投影如何计算。
- 前端如何展示目录、检索结果、散点图和详情页。

这些业务规则分别由采集线、解析线、索引线、可视化投影线和请求型读取能力定义。

横向层与纵向线的关系如下：

| 纵向线 | 横向层负责 | 纵向线负责 |
| --- | --- | --- |
| 采集线 | 创建历史采集或周期更新任务，按来源启动独立进程，控制同源互斥和总体并发，记录采集进度和历史效果 | 访问标准网站、翻页、解析元数据、判断入库动作、下载 PDF、写入采集结果 |
| 解析线 | 在采集线产生可解析 PDF 后创建解析任务，调度执行，记录任务状态和失败原因 | 读取 PDF、抽取正文、生成和校验 4 个 Markdown、写回 MinIO 和数据库 |
| 索引线 | 在解析成功后创建索引任务，调度执行，记录索引状态和失败原因 | 读取 `standard_overview.md`、生成 embedding、写入 `standard_indexes` |
| 可视化投影线 | 在周期更新结束、索引集合变化或后台重建后创建投影任务，保证新旧投影版本切换安全 | 读取有效标准 embedding、计算二维坐标、写入 Atlas 投影产物 |

### 后端实现与进程模型

后端使用 FastAPI 提供任务创建、状态查询和历史记录读取接口。FastAPI 请求只负责提交任务和读取状态，不直接执行长耗时任务。

任务管理器负责启动独立子进程执行后台任务。每次采集任务启动一个独立进程，国家标准、行业标准、地方标准采集器彼此隔离，不共享内存，通过数据库交换任务状态、进度和结果。

任务级隔离采用多进程模型，不以多线程作为主要任务管理方式。后续若需要优化单个采集器内部的网络 IO，可以在采集器内部局部使用线程或异步请求，但这不改变任务级多进程调度、互斥和失败恢复模型。

解析任务、索引任务和可视化投影任务也纳入同一任务管理器。它们可以不按“一个来源一个进程”划分，但同样不在 FastAPI 请求进程内直接执行。

### 任务调度与并发规则

任务类型包括：

- 历史采集任务：用于某个来源的首次或补充入库。
- 周期更新任务：按固定时间间隔检查外部网站变化。
- 解析任务：采集线下载可解析 PDF 成功后触发。
- 索引任务：解析线成功生成 `standard_overview.md` 后触发。
- 可视化投影任务：周期更新结束、索引集合变化或后台重建命令触发。

任务创建后先进入待执行队列。任务管理器按固定间隔扫描待执行任务，当当前运行进程数低于并发上限时，按任务优先级和创建时间选择下一条任务启动。优先级相同时，先创建的任务先执行。

同一来源的采集任务不允许并发执行。例如国家标准历史采集正在运行时，新的国家标准周期更新任务不能同时启动，应等待、跳过或标记为未执行，具体策略由任务配置决定。不同来源的采集任务可以并发执行，但总并发数受进程池上限控制。

采集、解析、索引和投影之间按纵向线的触发关系衔接。采集线只有在产生新的可解析 PDF 或文件变化时才创建解析任务；解析成功后创建索引任务；索引集合变化或周期更新结束后创建可视化投影任务。任务管理器只负责把这些任务排队和执行，不改变纵向线定义的触发条件。

### 状态、进度与历史记录

每个后台任务都需要保存一条任务总记录，用于展示当前执行状态和历史执行效果。任务总记录至少包含任务 ID、任务类型、来源、触发方式、任务状态、当前阶段、开始时间、结束时间、执行时长、最近心跳时间、进度百分比和错误摘要。

任务状态统一使用待执行、执行中、已完成、失败、已取消。当前阶段由具体任务写入，例如扫描列表、读取详情、下载文件、写入数据库、生成 Markdown、生成 embedding、计算投影。

采集任务需要记录核心进度字段：已扫描页数、已发现标准数、已处理标准数、需要下载文件数、下载成功文件数、下载失败文件数、总标准数和整体进度。进度不要求每条记录都刷新数据库，但每处理一页、一批标准或一个文件后应更新一次，保证前端和运维可以看到任务仍在推进。

采集任务还需要保存任务明细记录。每条明细对应一次任务中处理到的一条标准，记录 standard_id、标准号、来源、分类、详情页链接、元数据动作、文件处理决策、文件处理结果、失败原因和重试次数。历史任务效果以任务总记录为入口，必要时通过任务明细追踪单条标准为什么新增、变化、跳过、下载失败或不可下载。

### 失败、重试与恢复

任务进程正常结束时，任务管理器根据任务结果将状态更新为已完成或失败。任务进程异常退出时，任务状态标记为失败，记录退出原因和最后心跳时间，不影响其他正在运行的来源任务。

任务管理器定期检查执行中任务的心跳。若任务长时间没有更新心跳，视为心跳超时；确认对应进程已不存在或不可恢复后，任务标记为失败，并记录超时原因。

单条标准处理失败时，优先记录到任务明细，不中断整个来源任务；只有出现登录失效、官网结构不可解析、数据库不可写、对象存储不可用等任务级错误时，才中断当前任务并标记任务失败。

可重试错误包括网络超时、临时限流、对象存储短暂不可用、Embedding 服务临时失败等。可重试任务按重试次数和退避间隔重新入队；超过最大重试次数后标记失败。不可下载、官网明确不公开全文、仅在线阅读不属于失败，不进入解析和索引重试。

任务恢复以数据库记录为准。进程重启后，任务管理器扫描待执行和可重试任务继续执行；对心跳超时但状态仍为执行中的任务，先做进程存活检查，再决定恢复、失败或重新入队。

### 首页摘要统计

首页摘要读取线使用横向层任务记录展示最近一次周期更新结果。

有效标准数量不从任务记录读取，而是实时查询 `standards` 中的有效标准集，过滤条件为官网状态有效、已材料化、已索引。

最近周期更新时间、当前周期状态、新增现行标准数、失效标准数、失败标准数来自最近一次周期更新任务及其明细汇总。周期更新正在执行时，首页展示进行中状态；周期更新完成后，展示该轮任务统计。

新增现行标准数包括本轮官网新增的现行标准，以及由即将实施转为现行后进入有效标准集的标准。失效标准数统计本轮由有效状态转为失效状态的标准；地方标准从现行或有更新版转为废止时计入失效。失败标准数汇总本轮下载失败、材料化失败、索引失败和任务级失败；不可下载标准不计入失败标准数。

## 纵向线

### 采集线

#### 链路

标准网站 -> 发现标准列表 -> 解析标准元数据 -> 入库决策 -> 文件获取与存储 -> 写入数据库与任务记录 -> 输出。

采集线从官网入口开始，先按来源和分类发现标准列表，再进入详情页补齐字段，形成统一的标准元数据。

- 历史采集以全量发现和首次入库为主：遍历完整列表，入库不存在的标准，并在有可下载 PDF 时下载原件、存入 MinIO；若只支持在线阅读或不公开全文，则只记录元数据和在线地址。历史采集重跑时仍要经过入库决策，保证同一标准不会重复入库。
- 周期更新以变化发现为主：扫描最新列表和复查队列，将每条标准归入新增、已有标准元数据变化或无变化，再判断文件侧是否需要下载、不需要下载或不可下载。两种模式最终都写入标准主表、任务记录和任务明细；只有新增 PDF 下载成功，或已有标准文件变化并重新下载成功时，才触发解析线。

采集线覆盖三个来源：国家标准、行业标准、地方标准。每个来源都有历史采集和周期更新两种运行模式，因此调度视角下共有 6 个采集任务；实现视角下建议使用 3 个来源采集器，每个采集器提供 2 个入口函数或入口脚本，避免同一网站的列表解析、详情解析和下载逻辑重复。

```text
national_collector
  - historical_collect()
  - scheduled_update()

industry_collector
  - historical_collect()
  - scheduled_update()

local_collector
  - historical_collect()
  - scheduled_update()
```

团体标准、企业标准、国际标准、国外标准不纳入本期采集范围。

#### 1. 标准网站

本期实现国家标准、行业标准、地方标准三个来源。

`来源` 字段取粗粒度值：国家标准、行业标准、地方标准。`分类` 字段取来源下的细分值，三类来源的语义完全不同，需各自采集：

| 来源 | 分类语义 | 取值 |
| --- | --- | --- |
| 国家标准 | 标准性质 | 强制性国家标准（GB）、推荐性国家标准（GB/T）、指导性技术文件（GB/Z） |
| 行业标准 | 行业名称 | 76 个行业，两位字母代号加名称，如 AQ 安全生产、BB 包装、YD 通信 |
| 地方标准 | 行政区划 | 31 个省级行政区，如北京市、山西省、内蒙古自治区；省级下另有 365 个市级细分项 |

三个来源的网站入口：

| 来源 | 网站 | 入口 |
| --- | --- | --- |
| 国家标准 | 国家标准全文公开系统 | `https://openstd.samr.gov.cn/bzgk/std/` |
| 行业标准 | 行业标准信息服务平台 | `https://hbba.sacinfo.org.cn/` |
| 地方标准 | 地方标准信息服务平台 | `https://dbba.sacinfo.org.cn/` |

国家标准站以 `std_list_type?p.p1=` 参数区分标准性质，取值 1、2、3 分别对应上表三类。该站另有 `p.p1=6` 国家标准外文版，属同一标准的外文译本，不作为独立标准采集。

行业标准站列表数据由 `POST /stdQueryList` 返回 JSON，详情页为 `/stdDetail/{pk}`，采集脚本直接调用该接口，无需解析 HTML。列表接口请求体为表单编码，分页参数为 `current` 和 `size`，筛选参数包括 `key`、`ministry`、`industry`、`pubdate`、`date`、`status`。按行业采集时 `industry` 传行业名称，如 `通信`；站点状态筛选值为即将实施、现行、废止。76 个行业中 GF 国防工业、QJ 航天当前为 0 项，脚本需正常处理空结果。

地方标准站结构与行业标准站同源：列表数据由 `POST /stdQueryList` 返回 JSON，详情页为 `/stdDetail/{pk}`。列表接口请求体为表单编码，分页参数为 `current` 和 `size`，筛选参数包括 `key`、`ministry`、`industry`、`pubdate`、`date`、`status`。省级发布部门按钮使用 `ministry=省级发布部门代号`，如 `sxzjj14` 表示山西省；省级或市级行政区子菜单使用 `industry=行政区划名称`，如 `山西省`、`太原市`。请求时 `ministry` 与 `industry` 择一使用，不同时传。详情页若提供下载入口则记录或下载 PDF；若只提供 `/portal/online/{pk}` 在线阅读入口，则记录在线阅读地址。地方标准的入库分类按层级保存：省级标准只保存省份，如 `山西省`；市级标准同时保存省份和市级，如 `山西省 / 太原市`。站点状态筛选值为现行、有更新版、废止。部分市级行政区当前为 0 项，脚本需正常处理空结果。

#### 2. 发现标准列表

每个来源使用独立采集器，因为列表结构、筛选参数、分页方式和下载方式都不同；采集器之间只共用标准化输出结构、数据库写入接口和 MinIO 上传接口。

国家标准历史采集：

1. 分别遍历 `p.p1=1`、`p.p1=2`、`p.p1=3` 三个分类列表。
2. 每个分类从第一页开始请求，后续页使用列表页分页参数继续翻页，直到当前分类最后一页。
3. 解析列表页中的标准号、标准名称、状态、发布日期、实施日期和 `showInfo(hcno)` 详情主键，详情页链接组装为 `/bzgk/std/newGbInfo?hcno={hcno}`。
4. 只采集国家标准本体，不采集 `p.p1=6` 外文版作为独立标准。

国家标准周期更新：

1. 分别扫描 `p.p1=1`、`p.p1=2`、`p.p1=3` 三个分类的最新列表页，列表仍按发布日期或公开时间倒序读取。
2. 列表扫描产生三类处理结果：
   - 新增标准：库内不存在该标准号或详情页主键，进入详情读取和 PDF 下载流程。
   - 已有标准元数据变化：库内已存在，但官网返回的状态、标准名称、发布日期、实施日期、详情页链接等字段变化，进入详情页复查并更新元数据指纹。
   - 无变化：库内已存在且元数据指纹一致，只更新本轮检查时间。
3. 状态变化属于元数据变化的一种，包括即将实施转为现行、现行转为废止；不单独作为并列处理分支。
4. 新增扫描遇到连续多条已存在且元数据指纹无变化，或列表记录早于上次同步水位后，停止当前分类扫描。
5. 为补充最新列表扫描盲区，对库内即将实施标准和现行标准建立复查队列：即将实施标准按实施日期临近优先，现行标准按“最久未检查优先”，单轮复查数量由任务配置限制；复查结果仍归入新增、已有标准元数据变化、无变化三类。
6. 国家标准没有“有更新版”状态；新版本若在官网作为新标准发布，则按新增标准入库。旧标准是否废止只以旧标准自己的官网状态为准。

行业标准历史采集：

1. 遍历 76 个行业分类。
2. 对每个行业调用列表接口 `POST /stdQueryList`，请求体使用 `application/x-www-form-urlencoded`。
3. 请求参数固定包含 `current`、`size`、`key`、`ministry`、`industry`、`pubdate`、`date`、`status`；历史采集按行业遍历时 `industry=行业名称`，`ministry` 留空。
4. 历史采集不使用页面默认状态筛选，`status` 留空采全量，或按即将实施、现行、废止三个状态分批采集后去重。
5. 按接口返回的 `pages` 或 `total` 翻页，直到当前行业最后一页。
6. 解析接口返回的标准号 `code`、标准名称 `chName`、行业名称 `industry`、状态 `status`、发布日期 `issueDate`、实施日期 `actDate`、详情页主键 `pk`。
7. 访问 `/stdDetail/{pk}` 补齐详情字段；若详情页提供全文下载入口则记录下载地址，若只提供 `/portal/online/{pk}` 则记录在线阅读地址。

行业标准周期更新：

1. 按 76 个行业分别调用 `POST /stdQueryList`，优先扫描每个行业的最新页或最新备案时间窗口。
2. 周期更新不依赖页面默认状态筛选；最新扫描可将 `status` 留空，也可按即将实施、现行、废止三个状态分批扫描后按 `pk` 去重。
3. 列表扫描产生三类处理结果：
   - 新增标准：库内不存在该 `pk` 或标准号，进入详情读取和 PDF 下载流程。
   - 已有标准元数据变化：库内已存在，但接口返回的状态、标准名称、发布日期、实施日期、详情页链接等字段变化，进入详情页复查并更新元数据指纹。
   - 无变化：库内已存在且元数据指纹一致，只更新本轮检查时间。
4. 状态变化属于元数据变化的一种，包括即将实施转为现行、现行转为废止；不单独作为并列处理分支。
5. 新增扫描遇到连续多条已存在且元数据指纹无变化，或列表记录早于上次同步水位后，停止当前行业扫描。
6. 为补充最新列表扫描盲区，对库内即将实施标准和现行标准建立复查队列：即将实施标准按实施日期临近优先，现行标准按行业和“最久未检查优先”，单轮复查数量由任务配置限制；复查结果仍归入新增、已有标准元数据变化、无变化三类。
7. 行业标准没有“有更新版”状态；新版本若在官网作为新标准发布，则按新增标准入库。旧标准是否废止只以旧标准自己的官网状态为准。

地方标准历史采集：

1. 遍历省级行政区；需要市级细分时，再遍历该省下面的市级行政区。
2. 调用列表接口 `POST /stdQueryList`，请求体使用 `application/x-www-form-urlencoded`，中文参数按 UTF-8 百分号编码。
3. 请求参数固定包含 `current`、`size`、`key`、`ministry`、`industry`、`pubdate`、`date`、`status`。
4. 省级发布部门覆盖使用 `ministry=省级发布部门代号`、`industry` 留空；省级本体或市级明细使用 `industry=省份或市级名称`、`ministry` 留空。采集脚本不要同时传 `ministry` 和 `industry`。
5. 历史采集不使用页面默认状态筛选，`status` 留空采全量，或按现行、有更新版、废止三个状态分批采集后去重。
6. 按接口返回的 `pages` 或 `total` 翻页，直到当前行政区最后一页。
7. 解析接口返回的标准号 `code`、标准名称 `chName`、行政区划 `industry`、状态 `status`、发布日期 `issueDate`、实施日期 `actDate`、详情页主键 `pk`。
8. 入库分类由采集任务上下文决定：省级标准写省份；市级标准写省份和市级，格式为 `省份 / 市级`。
9. 访问 `/stdDetail/{pk}` 补齐详情字段；若详情页提供全文下载入口则记录或下载 PDF，若只提供 `/portal/online/{pk}` 则记录在线阅读地址。

地方标准周期更新：

1. 按省级行政区和必要的市级行政区调用 `POST /stdQueryList`，优先扫描最新页或最新备案时间窗口。
2. 周期更新不依赖页面默认状态筛选；最新扫描可将 `status` 留空，也可按现行、有更新版、废止三个状态分批扫描后按 `pk` 去重。
3. 列表扫描产生三类处理结果：
   - 新增标准：库内不存在该 `pk` 或标准号，进入详情读取和 PDF 下载或在线阅读地址记录流程。
   - 已有标准元数据变化：库内已存在，但接口返回的状态、标准名称、发布日期、实施日期、行政区划、详情页链接等字段变化，进入详情页复查并更新元数据指纹。
   - 无变化：库内已存在且元数据指纹一致，只更新本轮检查时间。
4. 状态变化属于元数据变化的一种，包括现行转为有更新版、现行转为废止、有更新版转为废止；不单独作为并列处理分支。
5. 新增扫描遇到连续多条已存在且元数据指纹无变化，或列表记录早于上次同步水位后，停止当前行政区扫描。
6. 为补充最新列表扫描盲区，对库内现行标准和有更新版标准建立复查队列，按地区和“最久未检查优先”分批复查详情页；复查结果仍归入新增、已有标准元数据变化、无变化三类。
7. 地方标准保留官网原始状态文本。“有更新版”只作为官网状态字段记录，不反推其他标准状态；标准是否废止只以该标准自己的官网状态为准。

#### 3. 解析标准元数据

本步骤负责把三个来源的官网原始字段转换为标准库统一元数据，不处理 PDF 正文内容；PDF 正文解析属于解析线。

状态字段保存官网原文。国家标准和行业标准的状态取值为即将实施、现行、废止；地方标准的状态取值为现行、有更新版、废止。有效标准过滤时，地方标准的“有更新版”按现行处理。

三个来源采集器都输出同一组标准化字段：

- 标准号
- 标准名称
- 来源：国家标准、行业标准、地方标准
- 分类：国家标准性质、行业名称、地方行政区划
- 发布日期
- 实施日期
- 状态
- 官网详情页链接
- PDF 下载链接或在线阅读链接
- 来源站点、来源范围、外部 ID
- 元数据指纹

国家标准字段映射：

- 标准号、标准名称、状态、发布日期、实施日期来自列表页。
- 分类来自 `p.p1` 对应的标准性质：强制性国家标准、推荐性国家标准、指导性技术文件。
- 详情页链接由列表页 `showInfo(hcno)` 组装为 `/bzgk/std/newGbInfo?hcno={hcno}`，`hcno` 作为外部 ID。
- PDF 下载链接或在线阅读链接来自详情页。

行业标准字段映射：

- 标准号取接口字段 `code`。
- 标准名称取接口字段 `chName`。
- 分类取接口字段 `industry`，保存行业名称，如 `通信`。
- 状态取接口字段 `status`。
- 发布日期、实施日期分别取接口字段 `issueDate`、`actDate`，入库前转换为日期。
- 详情页链接由 `pk` 组装为 `/stdDetail/{pk}`，`pk` 作为外部 ID。
- PDF 下载链接或在线阅读链接来自详情页。

地方标准字段映射：

- 标准号取接口字段 `code`。
- 标准名称取接口字段 `chName`。
- 状态取接口字段 `status`。
- 发布日期、实施日期分别取接口字段 `issueDate`、`actDate`，入库前转换为日期。
- 详情页链接由 `pk` 组装为 `/stdDetail/{pk}`，`pk` 作为外部 ID。
- 分类不直接照搬接口字段，而是由采集任务上下文生成：省级标准写省份，如 `山西省`；市级标准写省份和市级，格式为 `山西省 / 太原市`。
- PDF 下载链接或在线阅读链接来自详情页。

元数据指纹用于判断周期更新中的“已有标准元数据变化”。指纹至少包含标准号、标准名称、状态、分类、发布日期、实施日期、详情页链接、PDF 下载链接或在线阅读链接；不包含本轮检查时间、任务 ID、下载文件 hash 等运行时字段。

#### 4. 入库决策

本步骤负责将解析后的标准元数据与标准主表比对，决定本轮采集对该标准的处理动作。判断分为两层：第一层决定元数据动作，第二层决定文件处理动作。

第一层是标准主表比对。比对键按来源确定：

- 国家标准：优先使用详情页主键 `hcno`，其次使用标准号和详情页链接。
- 行业标准：优先使用详情页主键 `pk`，其次使用标准号和详情页链接。
- 地方标准：优先使用详情页主键 `pk`，其次使用标准号、分类和详情页链接。

元数据动作分为：

- 新增标准：标准主表不存在该标准，写入标准元数据。
- 已有标准元数据变化：标准主表已存在，但元数据指纹变化，更新对应字段。状态变化属于元数据变化的一种，不单独作为处理分支。
- 无变化：标准主表已存在且元数据指纹一致，只更新本轮检查时间和采集明细。

第二层是文件处理决策，决定是否进入下载、存储和后续解析：

- 需要下载：新增标准存在可下载 PDF；或已有标准的 PDF 下载入口、PDF 文件指纹发生变化。
- 不需要下载：已有标准只是状态、名称、发布日期、实施日期、分类、详情页链接等非文件字段变化，不重新下载、不重新解析、不重新索引。
- 不可下载：标准没有可下载 PDF，仅有在线阅读地址或官网明确不公开全文；元数据正常入库，但不进入解析线、索引线和有效标准集。

#### 5. 文件获取与存储

本步骤只处理第 4 步判定为“需要下载”的标准。仅元数据变化且不涉及文件变化的标准，不进入本步骤；判定为“不可下载”的标准只记录在线阅读地址或不可下载原因，不进入 PDF 下载。

PDF 获取方式按来源处理：

- 国家标准：从详情页解析下载按钮或在线阅读入口；存在可下载 PDF 时下载 PDF。
- 行业标准：从详情页解析全文入口；若提供 PDF 下载则下载，若只提供 `/portal/online/{pk}` 则记录在线阅读地址。
- 地方标准：从详情页解析全文入口；若提供 PDF 下载则下载，若只提供 `/portal/online/{pk}` 则记录在线阅读地址。

PDF 下载成功后，先在本地临时目录完成文件校验：

- 校验响应是否为 PDF。
- 校验文件大小是否大于 0。
- 计算文件 hash。
- 记录文件大小。

校验通过后，将 PDF 原件存入 MinIO，并把 bucket、object_key、文件 hash、文件大小写入标准主表。

若是新增标准，PDF 存储成功后加工状态置为已下载，并触发解析线。若是已有标准的文件变化，PDF 存储成功后更新文件字段，并重新触发解析线；解析成功后再触发索引线。

不可下载和下载失败需要区分记录：

- 不可下载：官网只提供在线阅读，或明确不公开全文；元数据正常入库，记录在线阅读地址，加工状态置为不可下载，不重试。
- 下载失败：网络异常、限流、超时、文件损坏等导致；记录失败原因，按重试策略处理。

#### 6. 数据库与任务记录

采集线不单独创建“采集数据库”或“解析状态数据库”，统一写入标准库数据库。采集相关记录分为主数据和任务记录两类。

`standards` 是标准主表，保存每条标准的当前快照：

- 基础元数据：标准号、标准名称、来源、分类、发布日期、实施日期、状态、官网详情页链接。
- 来源定位：来源站点、来源范围、外部 ID。国家标准外部 ID 为 `hcno`，行业标准和地方标准外部 ID 为 `pk`。
- 文件信息：PDF bucket、object_key、文件 hash、文件大小、PDF 下载链接或在线阅读链接。
- 处理状态：下载状态、材料化状态、索引状态。
- 更新判断字段：元数据指纹、上次同步时间、上次状态检查时间。

`standard_sync_jobs` 是一次采集任务的总记录，历史采集和周期更新都写入该表：

- 任务维度：来源、任务模式、采集范围、触发方式、任务状态、开始时间、结束时间。
- 进度维度：已扫描页数、已发现标准数、已处理标准数、总标准数、整体进度。
- 结果统计：新增数、元数据变化数、无变化数、需要下载数、不可下载数、下载成功数、下载失败数。
- 失败信息：任务级失败原因、最后错误信息。

`standard_sync_items` 是一次采集任务中每条标准的处理明细，用于追踪第 4 步和第 5 步的决策结果：

- 标准定位：standard_id、标准号、来源、分类、外部 ID、官网详情页链接。
- 元数据动作：新增标准、已有标准元数据变化、无变化。
- 文件决策：需要下载、不需要下载、不可下载。
- 文件结果：下载成功、下载失败、PDF object_key、文件 hash、文件大小、在线阅读地址。
- 变化记录：旧元数据指纹、新元数据指纹、变化字段摘要。
- 异常记录：失败原因、错误信息、重试次数。

`standard_processing_jobs` 是后续加工任务记录，只在采集线产生新的可解析 PDF 时创建或触发：

- 新增标准 PDF 下载成功后，创建解析任务。
- 已有标准文件变化并重新下载成功后，重新创建解析任务；解析成功后再触发索引线。
- 仅状态、名称、发布日期、实施日期、分类等非文件元数据变化时，不创建解析任务。

解析状态和索引状态不单独建库。标准主表保存当前加工状态，`standard_processing_jobs` 保存每次加工任务的执行记录。

#### 7. 输出

采集线输出三类结果：

- 标准主数据：写入或更新 `standards`，包括标准元数据、状态、来源定位、文件信息和加工状态。
- 文件对象：可下载 PDF 存入 MinIO；仅在线阅读的标准只记录在线阅读地址。
- 任务记录：写入 `standard_sync_jobs` 和 `standard_sync_items`，用于任务进度、历史记录、失败排查和首页统计。

采集线只有在产生新的可解析 PDF 时才触发解析线，包括新增标准 PDF 下载成功，以及已有标准文件变化后重新下载成功。仅元数据变化或不可下载标准不触发解析线。

覆盖前端：采集线无直接页面操作，统计结果经任务记录汇总后显示在首页摘要。

#### 8. 验收测试

采集线的测试以最终项目验收为主：启动前端、后端、PostgreSQL、MinIO 和任务进程后，通过页面或后台任务入口触发采集，再检查页面状态、数据库记录、MinIO 文件和后续解析任务是否一致。验收不要求每次都跑全量官网数据，优先使用小范围采集任务验证链路正确性。

基础采集验收：

1. 触发国家标准小范围采集，覆盖 `p.p1=1`、`p.p1=2`、`p.p1=3` 三个分类，确认页面任务进度正常推进，数据库中写入标准号、名称、状态、发布日期、实施日期、详情页主键和分类。
2. 触发行业标准小范围采集，选择一个非空行业，确认能调用 `POST /stdQueryList` 翻页，并在数据库中写入 `code`、`chName`、`industry`、`status`、`issueDate`、`actDate`、`pk` 对应字段。
3. 触发地方标准小范围采集，分别覆盖省级和市级任务，确认省级分类写省份，市级分类写 `省份 / 市级`，并确认请求没有同时使用 `ministry` 和 `industry`。
4. 对同一小范围重复执行历史采集，确认按第 4 步的来源比对键识别已有标准，不重复入库。

周期更新验收：

1. 准备或等待官网出现库内不存在的标准，执行周期更新后应判定为新增标准。
2. 人工构造或通过测试数据模拟官网状态、名称、发布日期、实施日期、分类或详情页链接变化，执行周期更新后应判定为已有标准元数据变化。
3. 对无变化的标准执行周期更新，只更新本轮检查时间和采集明细，不重复下载、不重复解析。
4. 国家标准和行业标准出现即将实施转现行、现行转废止时，任务明细记录为元数据变化。
5. 地方标准出现现行转有更新版、现行转废止、有更新版转废止时，任务明细记录为元数据变化。
6. 检查库内即将实施、现行、有更新版标准能进入对应复查队列，并按任务配置分批复查。

文件处理验收：

1. 新增标准存在可下载 PDF 时，MinIO 中出现 PDF 原件，`standards` 写入 bucket、object_key、文件 hash 和文件大小，并创建解析任务。
2. 已有标准 PDF 下载入口或文件 hash 变化时，重新下载 PDF，更新文件字段，并重新创建解析任务。
3. 已有标准只有非文件元数据变化时，不新增 MinIO 文件，不创建解析任务。
4. 仅在线阅读或官网明确不公开全文时，数据库记录在线阅读地址和不可下载状态，不重试，不创建解析任务。
5. 网络异常、限流、超时或文件损坏时，任务明细记录下载失败、失败原因和重试次数。

任务记录验收：

1. 每次历史采集和周期更新都能在页面看到任务状态，并在 `standard_sync_jobs` 中写入任务总记录。
2. 每条被发现的标准都写入 `standard_sync_items`，记录元数据动作、文件决策、文件结果和异常信息。
3. 页面统计与数据库统计一致：新增数、元数据变化数、无变化数、需要下载数、不可下载数、下载成功数、下载失败数，与明细记录汇总一致。
4. 同一来源上一轮采集未结束时，新一轮同来源采集不会并发执行，页面或任务记录能看到跳过或等待状态。

### 解析线

#### 链路

可解析 PDF -> 创建或认领解析任务 -> 读取 PDF 原件 -> 抽取 PDF 原文文本 -> 生成 `standard_body.md` -> 基于正文生成 `standard_structure.md`、`standard_logic.md`、`standard_overview.md` -> 校验 Markdown -> 写回 MinIO 与数据库 -> 输出。

解析线不再区分国家标准、行业标准和地方标准。三个来源进入本线时都已经被采集线统一为标准主表记录和 PDF 对象，本线只面向 PDF 原件和标准元数据工作。

#### 触发与输入

解析线由采集线自动触发，不单独参与周期调度。触发条件只有两类：

- 新增标准 PDF 下载并存储成功。
- 已有标准的 PDF 下载入口或文件 hash 变化，重新下载并存储成功。

仅官网状态、名称、发布日期、实施日期、分类、详情页链接等非文件元数据变化时，不触发解析线。不可下载标准和仅在线阅读标准也不进入解析线。

解析线输入是标准主表中已具备 PDF 文件信息、但尚未材料化成功的标准记录，主要包括：

- 标准定位：standard_id、标准号、标准名称。
- PDF 定位：source_pdf_bucket、source_pdf_object_key、source_pdf_hash、source_pdf_size_bytes。
- 任务定位：standard_processing_jobs 中的解析任务记录。

材料化失败的标准进入解析重试队列，由任务系统按重试策略自动重跑。重跑仍使用标准主表中的当前 PDF object_key，产物 object_key 保持稳定，成功后覆盖旧的 Markdown 产物并更新任务记录。

#### 处理规则

任务启动时先检查标准记录是否存在、PDF object_key 是否存在、MinIO 是否能读取 PDF。任一前置条件不满足，任务直接失败并记录错误原因，不进入 Markdown 生成。

解析服务从 MinIO 下载 PDF 到本地临时目录，再抽取 PDF 原文文本。临时文件只服务于本次任务，任务结束后清理，不作为长期产物保存。PDF 原文抽取保持章节顺序和正文内容为主，不在抽取阶段推断标准结构、章节关系或检索摘要。

本期不单独实现 OCR 兜底。扫描版 PDF 若无法抽取文本，按材料化失败处理，后续可作为解析能力增强项。

四个 Markdown 不是并列从 PDF 直接生成，而是先由 PDF 原文生成 `standard_body.md`，再以 `standard_body.md` 为统一事实来源生成另外三个产物。

| 产物 | 生成依据 | 作用 |
| --- | --- | --- |
| `standard_body.md` | PDF 原文文本 | 保存标准正文的 Markdown 化结果，去除目录类噪声，作为其他产物的基础材料 |
| `standard_structure.md` | `standard_body.md` | 描述标准自身的章节层级、内容板块和静态架构 |
| `standard_logic.md` | `standard_body.md` | 描述章节之间的承接关系、执行链路和内部逻辑 |
| `standard_overview.md` | `standard_body.md` | 生成面向检索的概要文本，作为索引线 embedding 的唯一输入 |

四个产物都需要包含 YAML front matter，至少记录标准名称、标准号、来源 PDF 和 document_role。`standard_overview.md` 额外记录 standard_id 和 schema_version，便于后续检索与版本兼容。

#### 校验、存储与状态

Markdown 生成后先做基础校验，再写回 MinIO。基础校验包括：

- 四个产物必须齐全，不允许缺少或多出产物类型。
- 每个 Markdown 必须有 YAML front matter，且 document_role 与产物类型一致。
- 正文不能为空。
- `standard_body.md` 必须包含可识别的正文标题或章节。
- `standard_overview.md` 必须包含标准基本信息、适用画像、典型检索命中描述、边界说明、检索摘要等检索概要部分。

校验通过后，四个 Markdown 以 `text/markdown; charset=utf-8` 写回 MinIO，并把 object_key 写入标准主表的 `body_md_object_key`、`structure_md_object_key`、`logic_md_object_key`、`overview_md_object_key` 字段。若上传或写库过程中失败，标准不应被置为已材料化；下一次重跑按稳定 object_key 覆盖产物。

解析成功后，标准主表的材料化状态置为已材料化，写入 materialized_at，并将索引状态重置为未索引，等待索引线处理。解析失败时，材料化状态置为材料化失败，记录 materialize_error，任务状态置为失败，不触发索引线。

解析线不新建独立数据库，继续写入标准库数据库。标准主表保存当前材料化结果，`standard_processing_jobs` 保存每次执行记录，包括任务状态、阶段、进度、开始结束时间和错误信息。

解析线成功后自动触发索引线。索引线只读取 `standard_overview.md` 生成 embedding；其余三个 Markdown 主要服务于详情页展示和 API 读取。

覆盖前端：界面 5 四个 Markdown tab 的内容来自本线产物。前端只读取和展示 Markdown，不参与解析任务编排。

#### 验收测试

解析线验收以单条标准的小范围任务为主，重点验证从 PDF 到四个 Markdown 的闭环。

1. 准备一条已有 PDF object_key 的标准记录，触发解析任务后，确认任务进度从读取 PDF、抽取文本、生成 Markdown、保存产物推进到完成。
2. 检查 MinIO 中出现四个 Markdown 产物，且内容非空。
3. 检查四个 Markdown 都包含 YAML front matter，document_role 分别对应 `standard_body`、`standard_structure`、`standard_logic`、`standard_overview`。
4. 解析成功后，`standards` 写入四个 Markdown object_key，materialize_status 置为已材料化，index_status 重置为未索引，并创建或触发后续索引任务。
5. 材料化失败后，materialize_status 置为材料化失败，materialize_error 和任务 error_message 记录原因，不触发索引线；进入重试队列后自动重跑，重跑成功可正常推进到索引线。

### 索引线

#### 链路

`standard_overview.md` -> 提取检索文本 -> 调用 Embedding 服务生成向量 -> 写入 `standard_indexes` -> 更新索引状态 -> 输出。

索引线只使用解析线生成的 `standard_overview.md`，不读取 `standard_structure.md`、`standard_logic.md`、`standard_body.md`。因此语义检索返回的是标准级结果，不做标准内部条款片段召回。

#### 触发与输入

索引线由解析线成功后自动触发，不单独参与周期调度。解析线每次成功材料化后，会把标准的 index_status 重置为未索引，等待索引线处理。

索引线输入包括：

- 标准定位：standard_id、标准号、标准名称。
- Markdown 定位：overview_md_object_key。
- 索引配置：embedding_model、embedding_dimensions、相似度度量与 pgvector 索引配置。

索引任务要求运行环境为 PostgreSQL + pgvector。若当前数据库不支持向量索引，任务应失败并记录错误原因，不把标准置为已索引。

#### 处理规则

任务启动后从 MinIO 读取 `standard_overview.md`，再抽取用于检索的文本。检索文本由标准名称、标准编号、来源 PDF 和 overview 正文组成；若提取结果为空，任务失败。

Embedding 服务返回向量后，系统校验向量维度必须与配置的 embedding_dimensions 一致。向量维度不一致、接口失败、超时或响应中缺少 embedding，均按索引失败处理，并按统一重试策略进入重试队列。

同一标准重建索引时，先删除 `standard_indexes` 中该标准已有的 `overview` 索引，再写入新索引，避免同一标准在语义检索中重复命中。

#### 存储与状态

`standard_indexes` 保存索引产物，字段包括 standard_id、index_kind、content、embedding、embedding_model、embedding_dimensions、content_hash、created_at、updated_at。当前 index_kind 固定为 `overview`。

索引成功后，标准主表的 index_status 置为已索引，写入 indexed_at，并清空 index_error。此时若官网状态有效且材料化状态为已材料化，该标准进入有效标准集，可被请求型读取接口访问。

索引失败时，index_status 置为索引失败，index_error 记录原因，计入首页失败标准数，不进入有效标准集。

覆盖前端：界面 3 的语义检索相似度得分依赖本线生成的向量；界面 1 的可视化投影线也读取本线生成的向量作为输入。

#### 验收测试

索引线验收以单条已材料化标准为主：

1. 准备一条已生成 `standard_overview.md` 的标准记录，触发索引任务后，确认任务读取 overview、生成 embedding、写入 `standard_indexes`。
2. 检查 `standard_indexes` 中该标准只有一条 `overview` 索引，embedding_model、embedding_dimensions、content_hash 与配置和文本一致。
3. 索引成功后，`standards.index_status` 置为已索引，indexed_at 有值，index_error 为空。
4. 索引失败后，`standards.index_status` 置为索引失败，index_error 记录原因，并进入自动重试队列。
5. 使用一条相关查询做语义检索时，已索引且官网状态有效的标准可以按相似度返回。

### 可视化投影线（界面 1 / Embedding Atlas）

#### 链路

有效标准集 -> 读取 `standard_indexes` embedding -> 生成投影版本 -> 计算二维坐标 -> 写入投影产物表 -> 标记版本完成 -> 输出。

可视化投影线服务首页标准可视化 tab 的 Embedding Atlas。它不是语义检索，也不是散点图读取接口；它是一个异步批量写任务，负责把高维 embedding 转成前端可渲染的二维坐标。前端聚类、标签排布、图例、着色维度切换和点击散点跳转详情都在界面侧完成。

#### 触发与输入

可视化投影线不由单条索引任务实时触发。它按全局批量任务运行，触发条件包括：

- 周期更新完成后，有新增有效标准、有效标准失效、标准重新材料化或索引集合变化。
- 后台执行索引重建后，需要重新生成首页可视化数据。
- 运维或管理入口手动触发可视化投影重算。

任务输入包括：

- 有效标准集：官网状态有效、已材料化、已索引。
- 向量索引：`standard_indexes` 中 `index_kind = overview`，且 embedding 模型和维度与当前配置一致的记录。
- 投影配置：投影算法、距离度量、随机种子、最小样本处理规则、输出版本号。

#### 处理规则

1. 任务开始时创建新的投影版本，状态为生成中，不影响线上正在读取的上一版完整投影。
2. 查询有效标准集，并与 `standard_indexes` 按 `standard_id` 关联，只保留存在有效 embedding 的标准。
3. 按稳定顺序组装 embedding 矩阵，推荐使用 `standard_id` 或标准号排序，保证同一输入集合在相同配置下尽量稳定。
4. 使用 cosine 距离对高维 embedding 做二维降维。默认建议使用 UMAP；样本量过少时使用固定小样本布局，避免降维算法因样本不足失败。
5. 将二维坐标归一化到前端容易渲染的数值范围，例如 `[-1, 1]` 或 `[0, 1]`；具体范围由接口契约统一。
6. 后端只计算每条标准的 x/y 坐标和可选颜色分组字段，不在后端生成簇标签。
7. 新版本所有点位写入完成并通过数量、维度和空值校验后，才把该版本标记为已完成并切换为当前版本。
8. 若任务失败，保留上一版完整投影继续供首页读取，不清空散点图数据。

#### 存储与状态

投影产物独立存储，不写入 `standards` 主表。

建议使用两类表：

- `standard_atlas_projections`：保存投影版本、算法、距离度量、embedding_model、embedding_dimensions、有效标准数量、已投影数量、缺失数量、任务状态、开始时间、完成时间和错误信息。
- `standard_atlas_points`：保存 projection_id、standard_id、x、y、color_key、source、category、created_at。

`standard_atlas_points` 不保存原始 embedding；原始 embedding 仍以 `standard_indexes.embedding` 为准。投影产物只服务首页可视化读取，不参与语义检索排序，也不改变有效标准判定。

覆盖前端：界面 1 的散点图数据读取线读取最新已完成投影版本，并把点位数组返回给 Embedding Atlas 渲染。

#### 边界与异常

- 无有效标准：生成一个已完成的空投影版本，点位数量为 0。
- 有效标准存在但缺少 embedding：该标准不进入本次点位，缺失数量写入投影版本记录。
- 当前数据库不是 PostgreSQL + pgvector：投影任务失败，因为无法稳定读取向量索引产物。
- embedding 模型或维度与当前配置不一致：对应索引不参与本次投影，避免新旧向量混用。
- 降维算法失败、依赖缺失或输出坐标包含空值：投影版本标记失败，不切换当前版本。
- 任务运行期间有效标准集再次变化：本次任务按启动时快照完成；下一轮任务再覆盖最新集合。

#### 验收测试

1. 有效标准已完成索引后，触发可视化投影任务，生成一个已完成的投影版本和对应点位记录。
2. 投影点位数量等于“有效标准中存在可用 overview embedding 的标准数量”，缺少 embedding 的标准计入缺失数量。
3. 每个点位都包含 `standard_id`、x、y 和分组字段，且 x/y 不为空、不为 NaN。
4. 投影任务失败时，上一版已完成投影仍可被散点图数据读取线读取。
5. 新增、失效或重新索引标准后，再次投影会生成新版本；新版本完成前首页仍读取旧版本。

## 请求型读取能力

触发方式：前端请求驱动，同步返回，不由任务管理调度。

作用域：有效标准集。请求型读取能力不共享一条业务链路，只共享有效标准过滤、权限预留、分页约定和统一错误返回。除语义检索依赖 pgvector 外，其余能力都按各自界面独立查询或读取，不互相触发，也不复用检索结果。

### 语义检索线（界面 3）

语义检索线服务界面 3 的自然语言标准检索，是请求型读取能力中唯一依赖 pgvector 的能力。它解决“用作业场景、对象、工序或风险点描述查找相关标准”的问题，返回标准级结果，不返回标准内部条款片段；详情页 Markdown 读取、目录查询和历史记录读取都不走本线。

#### 输入

前端调用 `POST /api/standards/search`，参数包括：

- `query`：用户输入的检索文本，必填。
- `limit`：返回条数，可选，默认使用系统配置，服务端限制为 1-20。

本期语义检索不接收来源、分类、发布日期等结构化筛选条件；这些条件属于目录查询线。

#### 数据来源

读取 `standards` 与 `standard_indexes`。`standards` 用于有效标准过滤和结果基础信息返回；`standard_indexes` 读取索引线写入的 `overview` embedding、检索文本、embedding 模型与维度。

查询文本先调用标准 Embedding 服务生成向量，再使用 PostgreSQL + pgvector 计算相似度。本线不读取 MinIO，不读取四个 Markdown 原文；Markdown 展开预览由详情与产物读取线按 standard_id 另行读取。

语义检索完成后会写入 `standard_search_queries` 与 `standard_search_results`，保存本次查询和结果快照，供检索历史线读取。这是本线唯一的写入副作用，不属于任务队列。`standard_search_queries` 保存查询文本、调用来源、limit、检索模式、embedding 模型、embedding 维度、结果数量、耗时、状态和错误信息；`standard_search_results` 保存当次结果的 query_id、standard_id、index_id、rank、score、match_level、命中说明与证据片段。

#### 处理规则

1. 前端空文本不发起请求；服务端收到空白 query 时返回空结果。
2. 服务端裁剪 `limit` 到 1-20。
3. 调用 Embedding 服务生成 query embedding，并校验向量维度与配置一致。
4. 在 `standards` 与 `standard_indexes` 关联结果中检索，只保留官网状态有效、已材料化、已索引，且 `index_kind = overview`、embedding 模型和维度与当前配置一致的记录。
5. 使用 pgvector cosine distance 排序，score 按 `1 - distance` 计算，按相似度由高到低返回。
6. 低于 `STANDARD_VECTOR_SEARCH_MIN_SCORE` 的结果不返回。
7. 检索结果按当前返回顺序写入历史快照，历史快照用于之后还原当次结果，不参与本次排序。

#### 输出

返回当前检索文本、检索模式、embedding 模型、embedding 维度和结果列表。

结果列表面向前端展示，字段包括 `standard_id`、标准名称、标准号、来源、分类、发布日期、实施日期、相似度得分、命中等级、命中说明和证据片段。前端用这些字段渲染检索结果表格，并通过 `standard_id` 进入标准详情。

`index_id`、官网状态、材料化时间、索引时间、同步时间、索引类型、embedding 模型和维度属于调试、审计或兼容字段；接口可以返回，但前端主展示不依赖这些字段。

#### 边界与异常

- 空 query：返回空结果，不调用 Embedding。
- 无有效标准或无命中：返回空 `matches`，前端显示暂无检索结果。
- 当前数据库不是 PostgreSQL + pgvector：返回空结果并附带可展示 message，说明标准向量检索不可用。
- Embedding 配置缺失、接口失败、超时或维度不一致：检索失败，前端展示错误信息，不降级为 SQL 查询。
- 索引模型或维度与当前配置不一致：对应索引不参与本次检索，避免新旧向量混算。

#### 验收测试

1. 输入与某条标准概要相关的自然语言描述时，已索引且官网状态有效的标准能按相似度返回。
2. 官网状态无效、未材料化、未索引、embedding 模型或维度不一致的标准不出现在结果中。
3. query 为空时不调用 Embedding，返回空结果。
4. PostgreSQL + pgvector 不可用时返回明确 message，前端能展示不可用原因。
5. 每次成功语义检索后，`standard_search_queries` 和 `standard_search_results` 中出现对应历史快照，历史读取时可还原当次结果。

### 目录查询线（界面 2）

目录查询线服务界面 2 的标准目录列表，用于浏览最近有效标准、按标准号或名称查找标准、按来源筛选结果，并从列表进入标准详情。它是结构化 SQL 查询，不做语义召回，不依赖 pgvector，也不读取 Markdown 产物。

#### 输入

前端调用标准目录查询接口，参数包括：

- `code`：标准号，精确或规范化后匹配。
- `keyword`：标准名称关键词。
- `source`：来源筛选，可选值为全部、国家标准、行业标准、地方标准。
- `page`：分页页码。
- `page_size`：每页条数，支持 10、25、50。

`code` 与 `keyword` 至少一个有值时视为有检索条件；只有来源筛选不改变默认时间范围。

#### 数据来源

只读取 `standards`。目录查询线使用标准主表中的标准 ID、标准号、标准名称、来源、分类、发布日期、实施日期、官网状态、材料化状态、索引状态和更新时间等字段。

本线不读取 `standard_indexes`，不调用 Embedding 服务，不使用 pgvector，不读取 MinIO，也不写入检索历史。

#### 处理规则

1. 查询层默认注入有效标准过滤：官网状态有效、已材料化、已索引。
2. 无标准号和名称关键词时，返回最近一个月的有效标准。
3. 输入标准号或名称关键词后，查询范围扩展为数据库中的全部有效标准，不受最近一个月限制。
4. 标准号查询优先做规范化精确匹配，避免空格、大小写或连接符差异影响命中；标准名称按关键词模糊匹配。
5. 来源筛选作用于当前结果集：无检索条件时筛选最近一个月有效标准，有检索条件时筛选全部有效标准中的命中结果。
6. 结果按发布日期或更新时间倒序返回；同一日期下按标准号或标准 ID 稳定排序。
7. 分页使用 `page` 与 `page_size` 计算 offset，服务端返回当前页数据和当前条件下的结果总数。
8. 有效标准总数与当前条件结果总数分开计算，不混用。

#### 输出

返回当前页标准列表、分页信息、当前条件结果总数，以及有效标准总数。

标准列表面向目录页展示，字段包括 `standard_id`、标准号、标准名称、来源、分类、发布日期、实施日期和更新时间。前端用这些字段渲染列表行，并通过 `standard_id` 进入详情与产物读取线。

#### 边界与异常

- 无有效标准：返回空列表，有效标准总数为 0。
- 无匹配结果：返回空列表，当前条件结果总数为 0，但有效标准总数保持真实值。
- `page_size` 不在允许范围内时使用默认值或返回参数错误，由接口实现统一决定。
- 页码超出结果范围时返回空列表，不回退到第一页。
- 来源参数不合法时返回参数错误，不静默忽略。

#### 验收测试

1. 无检索条件时，目录页只展示最近一个月内的有效标准，并按默认排序返回。
2. 输入标准号或名称关键词后，可以查询到最近一个月之外的有效标准。
3. 来源筛选只影响当前结果集，不改变有效标准总数。
4. 未材料化、未索引或官网状态无效的标准不出现在目录结果中。
5. 分页切换 10、25、50 时，当前页数据量和当前条件结果总数正确。

### 详情与产物读取线（界面 5）

详情与产物读取线服务界面 5 的标准详情页，用于展示单条标准的基础信息、来源信息和解析后的 Markdown 产物。它按 `standard_id` 定位标准，不承担搜索、筛选、排序或相似度计算职责。

#### 输入

前端从目录查询线、语义检索线或散点图数据读取线拿到 `standard_id` 后进入详情页。详情页读取包括两类请求：

- `standard_id`：标准 ID，用于读取标准基础信息和产物 object_key。
- `kind`：Markdown 产物类型，用于切换产物 tab，可选值为 `overview`、`structure`、`logic`、`body`。

#### 数据来源

读取 `standards` 与 MinIO。`standards` 提供标准基础信息、来源字段、官网详情页链接、PDF 原件信息、材料化状态、索引状态，以及四个 Markdown 产物的 object_key。MinIO 按 object_key 读取 `standard_overview.md`、`standard_structure.md`、`standard_logic.md`、`standard_body.md`。

本线不读取 `standard_indexes`，不调用 Embedding 服务，不使用 pgvector，也不写入检索历史。

来源网站 logo 是按来源预置的前端静态资源，不由采集线获取；前端根据来源字段映射到对应图片。官网跳转地址使用采集线写入 `standards.detail_url` 的官网详情页链接。

#### 处理规则

1. 根据 `standard_id` 读取标准主表记录；对前台详情页，默认只允许读取有效标准。
2. 返回基础信息时同时返回四个 Markdown 产物的 object_key 或可读状态，供前端渲染 tab。
3. 前端切换 Markdown tab 时，服务端按 `kind` 选择对应 object_key，从 MinIO 读取 Markdown 文本并以 `text/markdown; charset=utf-8` 返回。
4. `kind` 只允许四个固定值：`overview`、`structure`、`logic`、`body`。
5. 本线只读取解析线已经生成的产物，不触发解析、不触发索引、不修复缺失 object_key。

#### 输出

标准基础信息包括 `standard_id`、标准号、标准名称、来源、分类、发布日期、实施日期、官网状态、材料化状态、索引状态、官网详情页链接和四个 Markdown 产物状态。

Markdown 产物读取返回当前 `kind` 对应的 Markdown 文本。前端用基础信息渲染详情头部、来源 logo 和官网跳转入口，用 Markdown 文本渲染对应 tab，并支持源码视图、渲染视图和复制当前 Markdown。

#### 边界与异常

- `standard_id` 不存在：返回 404。
- 标准不在有效标准集内：前台详情页返回不可访问，后台管理入口可按权限另行放开。
- `kind` 不合法：返回参数错误。
- Markdown object_key 为空或 MinIO 对象不存在：返回产物缺失错误，前端在对应 tab 展示加载失败。
- MinIO 不可用或读取超时：返回读取失败，不降级为数据库字段内容。
- 官网详情页链接为空：前端不展示官网跳转入口或置为不可点击。

#### 验收测试

1. 从目录、语义检索结果或散点图点击标准后，能按 `standard_id` 打开同一条标准详情。
2. 详情页基础信息与 `standards` 中记录一致，来源 logo 按来源字段正确映射，官网跳转地址使用 `detail_url`。
3. 四个 Markdown tab 分别能读取对应产物，内容与 MinIO 中对象一致。
4. 复制当前 Markdown、源码/渲染视图切换不改变后端数据。
5. 产物缺失、`kind` 不合法或 `standard_id` 不存在时，前端能展示明确错误状态。

### 检索历史线（界面 3、界面 4）

检索历史线服务界面 3 的「检索历史」按钮和界面 4 的历史浮层，用于查看和复用历史语义检索结果。它读取语义检索线保存的结果快照，不重新发起检索，不重新调用 Embedding，也不重新计算相似度。

#### 输入

前端在检索结果页点击「检索历史」按钮时读取历史列表，参数包括：

- `limit`：返回条数，浮层默认 10 条。
- `offset`：可选，用于超出 10 条后的滚动加载或分页加载。

点击某条历史记录时，前端使用该记录的 `search_id` 读取或复用对应快照。

#### 数据来源

读取 `standard_search_queries` 与 `standard_search_results`。`standard_search_queries` 保存一次语义检索的查询文本、检索时间、调用来源、limit、检索模式、embedding 模型、embedding 维度、结果数量、耗时、状态和错误信息；`standard_search_results` 保存该次检索的结果快照、排序、得分、命中等级、命中说明和证据片段。

历史记录必须保存足够还原界面 3 的结果列表字段，不能只保存 query 和 standard_id。否则标准库更新后，历史回填会变成“用旧 query 看新数据”，与当时用户看到的结果不一致。

本线不读取 `standard_indexes`，不调用 Embedding 服务，不使用 pgvector，不读取 MinIO，也不重新查询有效标准集。

#### 处理规则

1. 历史列表按检索时间倒序返回。
2. 浮层默认显示 10 条，超过 10 条时前端在浮层内滚动查看。
3. 历史列表只展示语义检索相关记录，不混入目录查询、详情读取、散点图读取和首页摘要读取。
4. 每条历史记录展示检索文本和检索时间；可选展示当次结果数量和状态。
5. 点击历史记录时，直接回填该记录保存的结果快照，恢复检索框内容、检索结果和检索时间。
6. 点击历史记录不重新发起语义检索，不重新生成 query embedding，不重新计算 score。
7. 回填后，系统只更新该历史记录的排序时间，使该记录出现在历史列表第一条；查询文本、结果快照、score 和证据片段不改变。

#### 输出

历史列表返回 `search_id`、检索文本、检索时间、检索模式、结果数量、状态、错误信息和结果摘要。浮层用这些字段渲染历史记录行。

历史快照返回检索文本、检索时间和当次结果列表。结果列表字段与语义检索线的前端展示字段保持一致，包括标准号、标准名称、来源、分类、发布日期、实施日期、相似度得分、命中等级、命中说明和证据片段。前端用快照直接重建界面 3，不访问语义检索接口。

#### 边界与异常

- 无历史记录：返回空列表，浮层显示暂无检索历史。
- `search_id` 不存在：返回 404 或快照不存在错误。
- 历史记录状态为失败：仍可展示查询文本、检索时间和错误信息，但没有结果列表。
- 快照中的标准后来失效或被更新：历史回填仍展示当时检索结果列表，不因当前有效标准集变化而改变；但用户从历史结果点击进入标准详情时，详情与产物读取线按 `standard_id` 读取当前标准详情和当前 Markdown 产物。
- 快照字段不完整：前端展示可用字段，并记录数据缺失问题；后端不重新查询当前标准补齐。

#### 验收测试

1. 完成一次语义检索后，历史浮层能按时间倒序显示该查询。
2. 历史浮层默认显示 10 条，超过 10 条时可以滚动查看。
3. 点击历史记录后，检索框内容、检索结果和检索时间按快照回填，不触发新的 Embedding 调用。
4. 标准库更新后，点击旧历史记录仍还原当时检索结果列表；再点击结果行进入详情时，展示该标准的当前详情和当前 Markdown 产物。
5. 回填历史记录后，该记录仅更新时间字段并出现在历史列表第一条，快照内容不变。

### 散点图数据读取线（界面 1）

散点图数据读取线服务界面 1 的标准可视化 tab，用于把全量有效标准一次性送给前端 Embedding Atlas 渲染。它只读取可视化投影线生成的二维坐标和标准基础字段，不负责计算 embedding、不负责降维投影、不负责聚类。

#### 输入

前端进入首页标准可视化 tab 时发起读取请求。本线默认不分页，一次性返回整张图所需数据。

可选参数包括：

- `color_by`：着色维度，默认按来源着色，可预留按行业、地区或分类着色。
- `projection_version`：可选，用于前端缓存校验；缺省时返回当前最新投影。

本线不接收语义检索文本、目录关键词、分页页码或每页条数。

#### 数据来源

读取 `standard_atlas_projections`、`standard_atlas_points` 和 `standards`。投影版本表保存投影版本、算法、状态和更新时间；投影点位表保存每条有效标准的二维坐标；`standards` 提供标准 ID、标准号、标准名称、来源、分类、发布日期、实施日期等前端展示和跳转所需字段。

投影产物由可视化投影线维护，每轮需要重算时对全量有效标准整体覆盖。投影表独立于标准主表，不把 x/y 坐标写入 `standards`，避免影响常规查询。

本线不读取 `standard_indexes.embedding` 做实时计算，不调用 Embedding 服务，不使用 pgvector 做检索，不读取 MinIO，也不读取检索历史。

#### 处理规则

1. 查询当前最新投影版本。
2. 只返回当前仍属于有效标准集，且在最新投影版本中存在坐标的标准。
3. 若某条有效标准尚无投影坐标，本次散点图不返回该点，并在摘要中返回缺失数量，供前端或监控提示投影需要刷新。
4. 按稳定顺序组装数组，推荐按来源、分类、标准号或 standard_id 排序；所有等长数组必须使用同一顺序。
5. `x`、`y` 只表示投影坐标，不携带业务主键；业务主键通过同下标的 `ids` 数组映射。
6. `category` 返回整数分类索引，`categories` 返回索引到分类名称、颜色和数量的映射。
7. 前端聚类、标签排布、图例展示、着色维度下拉和点击散点跳转详情都在界面侧完成；后端只提供渲染所需数据。

#### 输出

返回投影版本、投影更新时间、有效标准数量、已投影数量、缺失投影数量，以及 Embedding Atlas 渲染所需数组。

数组字段包括：

- `x`：每个标准的 x 坐标。
- `y`：每个标准的 y 坐标。
- `category`：每个标准对应的分类索引。
- `ids`：每个点对应的 `standard_id`。
- `names`：每个点对应的标准名称。
- `codes`：每个点对应的标准号。

同时返回 `categories` 图例数据，包括分类索引、分类名称、颜色和该分类下标准数量。`ids` 用于点击散点后跳转标准详情，`names` 供前端在 `queryClusterLabels` 回调内生成簇标签。

#### 边界与异常

- 暂无有效标准：返回空数组，有效标准数量为 0。
- 暂无投影版本：返回空数组和明确状态，前端显示可视化数据生成中或暂无可视化数据。
- 部分有效标准缺少投影坐标：返回已有坐标点，并返回缺失数量；不在读取接口中临时计算坐标。
- 投影版本正在重算：读取上一版完整投影；新版本完成整体覆盖后再切换，避免前端看到半成品。
- 坐标数组长度不一致：后端应返回错误，不返回不完整数据。
- `color_by` 不支持：返回参数错误或回退默认来源着色，由接口实现统一决定。

#### 验收测试

1. 有效标准集存在且投影任务完成后，接口一次性返回整张散点图所需数据，不分页。
2. `x`、`y`、`category`、`ids`、`names`、`codes` 数组长度一致，且同一数组下标指向同一条标准。
3. 点击散点时，前端能通过 `ids[index]` 进入对应标准详情。
4. 聚类标签生成时，前端能通过 `names` 找到当前簇内标准名称并生成中文标签。
5. 投影任务重算期间，读取接口仍返回上一版完整投影，不返回半量数据。
6. 新增有效标准后，在投影任务未完成前缺失投影数量增加；投影任务完成后该标准出现在散点图中。

### 首页摘要读取线（界面 1、界面 2 顶部）

首页摘要读取线服务界面 1 和界面 2 顶部摘要区，用于展示标准库当前整体状态和最近一次周期更新结果。它只提供全局摘要，不受目录查询条件、来源筛选、分页、语义检索和散点图视口影响。

#### 输入

前端进入首页或刷新首页摘要时发起读取请求。本线不需要业务查询参数。

可选参数只用于控制刷新行为，例如是否强制重新读取数据库；不接收标准号、关键词、来源、分页页码或语义检索文本。

#### 数据来源

有效标准数量查询 `standards` 中的有效标准集，过滤条件与其他读取能力一致：官网状态有效、已材料化、已索引。

其余摘要字段来自横向层任务执行记录，主要读取 `standard_sync_jobs` 和必要的 `standard_sync_items` 汇总。最近周期更新时间、当前周期状态来自最近一次周期更新任务；新增现行标准数、失效标准数、失败标准数来自该任务及其明细统计。

本线不读取 `standard_indexes`，不调用 Embedding 服务，不使用 pgvector，不读取 MinIO，也不读取检索历史。

#### 处理规则

1. 有效标准数量按当前数据库实时统计，不使用目录查询线的当前条件结果总数。
2. 最近周期更新时间取最近一次周期更新任务的完成时间；任务仍在执行时取任务更新时间或开始时间用于展示“进行中”状态。
3. 当前周期状态来自最近一次周期更新任务状态，映射为未开始、进行中、已完成、完成但有失败、失败等前端可展示状态。
4. 新增现行标准数包括本轮官网新增的现行标准，以及由即将实施转为现行后进入有效标准集的标准。
5. 失效标准数统计本轮由有效状态转为失效状态的标准；地方标准从现行或有更新版转为废止时计入失效。
6. 失败标准数汇总本轮下载失败、材料化失败、索引失败和任务级失败；不可下载标准不计入失败标准数。
7. 首页摘要是全局状态，目录查询、来源筛选和语义检索不会改变摘要结果。

#### 输出

返回有效标准数量、最近周期更新时间、当前周期状态、新增现行标准数、失效标准数和失败标准数。

界面 1 和界面 2 顶部使用同一份摘要结果。周期更新进行中时，前端只展示“周期更新 · 进行中”和必要的时间信息；周期更新完成后，再展示新增现行标准数、失效标准数和失败标准数。

#### 边界与异常

- 尚无周期更新任务：有效标准数量仍正常返回，其余任务字段返回空值或 0，状态为未开始。
- 周期更新正在执行：返回当前任务状态和已有统计，前端展示进行中状态。
- 最近任务失败：返回失败状态、失败标准数和错误摘要，不影响有效标准数量读取。
- 任务明细缺失或统计字段为空：按 0 处理，并保留任务状态。
- 有效标准数量读取失败：摘要接口返回错误，前端展示摘要读取失败，不使用目录列表数量兜底。

#### 验收测试

1. 首页两个 tab 顶部显示的有效标准数量一致，且不受目录检索、来源筛选和分页影响。
2. 有效标准数量只统计官网状态有效、已材料化、已索引的标准。
3. 周期更新进行中时，摘要区显示进行中状态，不展示已完成口径的新增、失效、失败汇总。
4. 周期更新完成后，最近更新时间、当前周期状态、新增现行标准数、失效标准数和失败标准数与任务记录汇总一致。
5. 无周期更新任务时，摘要接口仍返回有效标准数量，任务相关字段为空值或 0。
